# PRD：3D 赛璐璐桌游店模拟经营游戏（Web 原型）

## 1. 项目信息

- **Language**: 简体中文
- **Programming Language**: 不锁定，建议 Vite + Three.js（MeshToonMaterial + 描边）+ React/原生 DOM，由架构师定
- **Project Name**: boardgame_shop_tycoon
- **交付形态**: Web 浏览器可玩原型，源码 ≤20 个文件
- **原始需求复述**: 玩家扮演桌游店老板，经营一家包含桌游售卖、体验区、周边收藏的店铺。核心玩法为日常运营（进货/定价/布局升级）、顾客互动（独特偏好与故事线）、周边收集（稀有品解锁特殊效果或剧情）。需有经济系统平衡收支、季节性活动与随机事件，整体为 3D 赛璐璐卡通渲染风格。

## 2. 产品定义

**一句话核心体验**: 在卡通手绘画风中，用每日"开门迎客—结算决策"的节奏，把一家小桌游店一步步经营成街区名店。

**Product Goals**:
1. 提供清晰、有节奏的回合制经营循环，让玩家每"一天"都有明确决策点和即时反馈（P0 目标：5 分钟内理解全部核心操作）。
2. 建立可信的经济模型：收支有压力、定价有博弈、升级有回报，避免"躺赢"或"必死"。
3. 用顾客偏好/故事线与周边收藏提供情感目标与长期成长感，支撑重复游玩。

**User Stories**:
1. As a 店主玩家, I want 每日开始前决定进货清单与定价 so that 我能在库存成本和预期销量间做取舍。
2. As a 店主玩家, I want 看到不同顾客在店内浏览、试玩、购买的行为 so that 我能直观理解他们的偏好并调整经营策略。
3. As a 剧情向玩家, I want 与常客多次互动解锁他们的个人故事 so that 经营之外有情感追进的动机。
4. As a 收集向玩家, I want 获得稀有周边并触发特殊效果/剧情 so that 我有长期的收集目标和惊喜时刻。
5. As a 策略玩家, I want 在结算画面看到当日盈亏与声望变化 so that 我能复盘并规划升级/扩建节奏。

## 3. 需求池（优先级表格）

P0 = 必须有（原型可玩的最小闭环），P1 = 应该有（完整体验），P2 = 锦上添花（可裁剪）。

| # | 模块 | 需求 | 优先级 |
|---|------|------|--------|
| 1 | 核心循环 | 每日回合制推进：开门营业 → 顾客到访（实时模拟一段时长）→ 日结 → 决策（进货/定价/升级）→ 次日 | P0 |
| 2 | 经济系统 | 现金为唯一资源；进货消耗现金、销售产生收入；每 7 天结算一次租金账单；资金 <0 即破产（游戏结束） | P0 |
| 3 | 经济系统 | 定价机制：每类商品可在指导价 ±50% 内调价；定价影响顾客购买概率与满意度 | P0 |
| 4 | 商品系统 | 至少 4 类商品：桌游（低/高价两档）、饮品零食、周边商品；各有进货价、指导价、热度参数 | P0 |
| 5 | 顾客系统 | 至少 4 种顾客类型（学生党、核心玩家、收藏家、路人），各有偏好品类、消费力区间、耐心值 | P0 |
| 6 | 顾客 AI | 行为状态机：进店 → 浏览货架/体验区 → （满足偏好则购买，否则概率流失）→ 离店；等待过久耐心耗尽流失 | P0 |
| 7 | 声望系统 | 顾客满意度累计为声望；声望提升顾客到访率与高消费顾客比例 | P0 |
| 8 | 店铺成长 | 至少 3 级升级线：体验区扩建（提高容量/体验收入）、货架扩容（提高库存上限）、装修档次（提升满意度加成） | P0 |
| 9 | 日结画面 | 展示当日收入/成本/净利、客流、满意度、声望变化、剩余资金，进入次日决策 | P0 |
| 10 | UI 框架 | HUD（日期、资金、声望、当日目标）+ 三个面板（进货/定价、店铺升级、顾客/收藏图鉴）+ 日结画面 | P0 |
| 11 | 3D 表现 | Three.js 赛璐璐渲染：MeshToonMaterial + 模型描边；斜 45° 等距视角；店内固定场景（货架、体验桌、收银台） | P0 |
| 12 | 3D 表现 | 顾客以卡通小人模型在店内移动、停留、做出购买动作；视觉反馈（爱心/怒气气泡图标） | P1 |
| 13 | 顾客故事线 | 至少 3 位有名字的常客：到访次数 + 满足其偏好 → 推进个人剧情（2-3 段对话事件），完成给予一次性奖励 | P1 |
| 14 | 周边收藏 | 周边分 3 档稀有度（普通/稀有/传说）；图鉴展示；稀有/传说周边解锁特殊效果（如客流 +10%）或隐藏剧情 | P1 |
| 15 | 随机事件 | 每日开始概率触发事件（如"网红探店：今日客流翻倍""快递延迟：部分进货未到"），带简单选择或纯通知 | P1 |
| 16 | 季节活动 | 按游戏内日期划分季节（如每 30 天轮换），季节影响商品热度；特定季节触发活动周（收益加成） | P2 |

## 4. 核心游戏循环（一天的文字化描述）

1. **晨间决策阶段**：弹出日结/晨报界面，玩家查看昨日结果 → 决定是否进货（各品类数量）、调整定价、购买升级 → 触发当日随机事件（如有）→ 点击"开门"。
2. **营业阶段（实时，默认 90 秒，可 2 倍速）**：3D 场景中顾客陆续进店，在货架与体验区之间移动；玩家可点击顾客查看其偏好与心情气泡；满意则购买（收银台结算动画），不满则流失。声望与资金实时更新于 HUD。
3. **打烊结算阶段**：营业结束进入日结画面，展示收入/成本/净利/客流/满意度/声望变化与里程碑提示（如解锁新常客剧情、获得新周边）。
4. **周期性压力**：每 7 天（每周）从资金扣除租金；资金 <0 破产结束；达成目标声望（如 100）触发"名店"结局/自由经营模式。

## 5. 数值框架草案

以下为原型参考区间，供架构师与工程师实现与调参：

| 项目 | 数值区间/规则 |
|------|--------------|
| 初始资金 | 3,000 – 5,000 金币（默认 4,000） |
| 商品进货价 | 低价桌游 30–60；高价桌游 120–200；饮品零食 8–15；普通周边 20–40；稀有周边 80–150 |
| 商品指导价 | 进货价 × 1.5 – 2.0；允许调价范围 ±50%；定价每高于指导价 10%，购买概率约 -8% |
| 租金/账单 | 每 7 天结算一次，400–800 金币（随店铺等级提升：1 级 400 / 2 级 600 / 3 级 800） |
| 每日客流 | 基础 8–15 人/天；声望每 +10 点约 +1 人；事件与季节可 ±50% |
| 顾客消费力 | 学生党 20–80；路人 30–100；核心玩家 100–300；收藏家 150–500（稀有周边主要买家） |
| 顾客耐心 | 30–60 秒；体验区占用时长 15–30 秒；耐心耗尽则流失并 -1 满意度 |
| 满意度/声望 | 满意顾客 +1~+2，流失 -1；声望初始 0，目标 100 达成"街区名店"；预期 20–30 个游戏日通关 |
| 升级成本 | 1→2 级约 1,500；2→3 级约 3,500（单条线）；体验区每级 +2 个体验位 |
| 体验区收入 | 每个体验位产生顾客消费概率加成 +20%，或直接收取体验费 10–25/人 |
| 稀有周边掉落 | 进货时 5–10% 概率附带稀有款，1–2% 传说款；持有传说周边解锁客流 +10% 或隐藏剧情 |
| 破产线 | 资金 < 0 于账单日结算时判定 |

## 6. UI 界面框架（布局草案）

- **主界面（营业中）**：3D 店铺场景全屏；顶部 HUD 栏（日期/季节、资金、声望条、当日客流计数）；右下"加速/打烊"按钮；点击顾客弹出小卡片（类型、偏好、心情）。
- **晨间决策界面**：左侧进货清单（品类、单价、数量、总价），右侧定价滑杆与升级按钮，底部"开门"主按钮。
- **日结界面**：居中卡片，分栏展示收支明细、客流漏斗（进店→购买→流失）、声望变化、解锁提示。
- **图鉴面板**：Tab 切换"常客故事 / 周边收藏"，展示进度与未解锁剪影。

## 7. 3D 赛璐璐美术表现要求

- 渲染：MeshToonMaterial（2-3 阶色调分离）+ 外轮廓描边（inverted hull 或后处理 outline 二选一，取性能友好者）。
- 场景：单个固定店铺室内场景，斜 45° 等距相机（可轻微缩放/平移，不需自由旋转）；货架、2-4 张体验桌、收银台、装饰物。
- 角色：低多边形 Q 版小人，4 种顾客类型用配色/配饰区分；行走/停留/购买/离开四种简单动画或位移动效。
- 氛围：暖色主调、高饱和、柔和阴影；营业/打烊有昼夜光照差异。
- 性能：原型目标 60 FPS @ 1080p，同屏顾客 ≤ 12 人。

## 8. 待确认问题

1. **单局时长预期**：按数值草案，通关约 20–30 个游戏日（现实时间约 40–60 分钟），是否符合预期？还是希望更短的单局体验？
2. **操作深度**：营业阶段是否允许玩家实时干预（如点击引导顾客、手动打折促销），还是纯观望+事后决策？目前按"轻干预（查看顾客信息）+ 事前决策"设计。
3. **故事线呈现形式**：对话事件用纯文本弹窗即可，还是需要角色立绘/表情差分？（影响美术工作量，原型建议纯文本 + 气泡）
4. **范围裁剪确认**：P2 项（音效、存档、贷款、季节轮换完整版）若工期紧张可全部裁剪，是否认可此优先级排序？
